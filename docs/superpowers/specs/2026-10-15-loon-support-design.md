## 功能范围

Loon 支持 CDT 分类用量、ECS 状态、可选余额与账单、系统通知、Telegram、Webhook、通知重试、日报、历史、阈值停机、定时启停与保活。默认只读；自动控制仍由原有 allowControl、实例信息、实时查询结果和阈值条件共同约束。

提供手动刷新、历史输出、通知测试、配置导入和手动启停入口。Loon 手动控制使用明确的操作、账号 ID 与完整实例 ID 确认，不把定时运行或普通查询解释为手动控制。基于经核实的 Loon 手动脚本机制实现，不伪造 Surge 的 $trigger 或直接取消原有触发检查。

## 平台适配

- 共享签名、流量计算、策略、状态、锁与重试逻辑；平台差异集中处理。
- Surge 继续使用模块参数替换；Loon 使用其支持的插件参数读取机制，并映射到同一套配置校验。具体语法以官方文档及可核实样例为准。
- HTTP 超时按平台转换：Surge 使用秒，Loon 使用毫秒。分别验证阿里云请求与 Webhook 请求；重定向等选项按平台支持情况处理。
- Surge 保留原生面板。Loon 使用受支持的手动脚本结果展示与日志，告警和日报使用通知。普通定时查询不逐次推送结果通知。
- 适配结束回调与本地存储语义，确保锁释放、运行超时、错误输出和敏感数据脱敏正确。
- 两个平台在各自应用中存储配置与历史，不承诺跨应用自动迁移。

## 构建与发布

构建从同一参数定义生成平台产物，更新 release-info、release-notes、INSTALL-URLS 及校验工具中的路径。安装 URL 指向 main 下的平台目录；版本脚本指向配套的新发布版本，不引用未包含 Loon 文件的旧 v0.3.3 标签。

旧 Surge 用户需一次性更换到 surge/ 下的新安装来源，迁移步骤写入 Surge 文档。远程链接仅在对应仓库文件及标签实际发布后生效；本地修改完成不等同于已发布。仓库元数据与实际 GitHub 仓库路径核对后统一生成链接。

## 数据流与错误处理

平台入口读取参数及操作 → 共享配置校验 → 获取运行锁 → 查询云 API → 根据显式操作执行策略 → 保存历史与通知队列 → 平台化输出并释放锁。

配置无效时不使用旧控制配置继续执行。云 API 查询失败保留旧数据并标注错误，不以失败结果触发启停。超时及不确定控制结果沿用冷却机制。通知失败保留队列以供后续重试。

## 验证标准

1. 构建可重复运行，生成的文件和引用均位于预期平台目录。
2. 原有签名、监控、策略与发布测试通过，路径断言随迁移更新。
3. Loon 模拟环境覆盖参数解析、请求超时、正常查询、错误结束、锁释放、通知、历史及显式手动控制；覆盖拒绝非显式控制和实例确认不匹配。
4. 核对两平台文档链接、安装入口与发布版本引用一致。
5. Windows 环境能完成 Node 构建与模拟测试；Surge/Loon 原生客户端验证和真实阿里云调用需在对应设备及用户配置下完成，结果报告区分已验证与待设备验证项。

## 文档安排

根 README 提供项目定位、功能摘要、surge/loon 入口、目录布局和真实构建测试命令。surge/README.md 保留原有完整配置和行为说明，并修正迁移后的链接。loon/README.md 单独说明插件安装、参数输入、定时任务、手动调用、结果查看和设备验证步骤。

已核对功能范围、目录职责、发布版本约束和测试边界。没有增加后台服务或独立 Web 界面；Loon 的 UI 展示不等同于 Surge 面板。平台 API 语法核实是实现前置工作，不能用假定接口替代测试。

# CDT Monitor Surge 模块安装说明

适用版本：v0.4.1。仓库已更名为 CDT-Monitor-Surge-Loon；旧来源需改为新仓库 surge/ 下的地址，随后在原模块中点“更新模块”。通过 GitHub URL 安装后，在 Surge 模块参数表直接填写账号和监控设置，无需后台或修改 JavaScript。

## 一 准备账号

请使用 Surge iOS 5.9.0 或更新版本、Surge Mac 5.7.5 或更新版本。Mac 的参数表从 5.5.0 起可用，但本模块的面板需要 5.7.5。iOS 还需具备相应面板功能授权。[官方模块参数表](https://manual.nssurge.com/profile/module.html)、[面板版本和授权说明](https://manual.nssurge.com/tools/panel.html)、[iOS 更新记录](https://kb.nssurge.com/surge-knowledge-base/release-notes/surge-ios)

准备阿里云 RAM AccessKey ID 和 Secret、实例地域、完整 ECS 实例 ID。只查看 CDT 流量时，`instance_id` 保留“未设置”。查询流量需要 CDT 读取权限；查询实例状态还需要 `ecs:DescribeInstanceStatus`。可在 RAM 控制台查看官方 `AliyunCDTReadOnlyAccess` 策略；启停、余额和账单属于后续按需增加的权限。[CDT 权限说明](https://help.aliyun.com/en/cdt/security-and-compliance/cdt)、[ECS 状态查询权限](https://help.aliyun.com/zh/ecs/developer-reference/api-ecs-2014-05-26-describeinstancestatus)

AccessKey 只填写到你自己的 Surge 中。不要将真实凭据写入 GitHub 文件或 URL；参数表、数据备份及导出的设置可能包含这些凭据，不要分享填写后的配置。

## 二 Mac 通过 URL 安装

1. 打开 Surge 主窗口，进入 **更多 → 模块**，选择 **从 URL 安装模块**（部分版本叫“安装新模块”）。
2. 粘贴以下完整地址，按界面提示安装：

```text
https://raw.githubusercontent.com/MavisTok/CDT-Monitor-Surge-Loon/refs/heads/main/surge/CDT-Monitor-Mac.sgmodule
```

3. 打开 **CDT Monitor 本地版** 的模块参数表，按照第四节填写账号。
4. 勾选启用并应用。确认脚本功能已开启，等待外部脚本下载完成。
5. 在主窗口 **面板** 或菜单栏 Surge 的 **面板 / Panels** 中，打开 **CDT Monitor** 并刷新。

名称中的“本地版”指监控逻辑在 Surge 内运行；模块和脚本通过 GitHub 下载，不需要你部署服务。

支持 URL Scheme 的版本也可将以下整行复制到浏览器地址栏，允许打开 Surge。Mac 使用 `surge` Scheme 需 6.7.0+；其他版本使用上面的模块管理页安装方式。GitHub 页面可能不会把自定义 Scheme 渲染为可点击链接。[官方 URL Scheme 文档](https://manual.nssurge.com/tools/url-scheme.html)

```text
surge:///install-module?url=https%3A%2F%2Fraw.githubusercontent.com%2FMavisTok%2FCDT-Monitor-Surge-Loon%2Frefs%2Fheads%2Fmain%2Fsurge%2FCDT-Monitor-Mac.sgmodule
```

## 三 iPhone / iPad 通过 URL 安装

1. 在 Surge 的模块管理页选择 **安装新模块 / 从 URL 安装**。
2. 粘贴以下完整地址：

```text
https://raw.githubusercontent.com/MavisTok/CDT-Monitor-Surge-Loon/refs/heads/main/surge/CDT-Monitor.sgmodule
```

3. 在模块参数表填写第四节的项目，启用并保存模块。
4. 开启脚本功能，保持 Surge 引擎运行，等待脚本自动下载。
5. 进入 **策略选择页**，找到 **CDT Monitor** 面板并点击刷新。

Surge iOS 5.10.0+ 也可将以下整行复制到 Safari 地址栏打开 Surge，然后完成安装和参数填写；5.9.0 请使用上面的模块管理页安装方式。[官方版本记录](https://kb.nssurge.com/surge-knowledge-base/release-notes/surge-ios)

```text
surge:///install-module?url=https%3A%2F%2Fraw.githubusercontent.com%2FMavisTok%2FCDT-Monitor-Surge-Loon%2Frefs%2Fheads%2Fmain%2Fsurge%2FCDT-Monitor.sgmodule
```

URL 安装无需复制任何 JS。首次安装及更新需要能访问 `raw.githubusercontent.com`；下载后脚本缓存在 Surge，查询仍需要联网访问阿里云。

**只启用一份 CDT 模块。** 从旧版迁移时先保留原参数、停用旧模块，再安装并填回参数。多账号模式继续选择 `config_source=local`。同名脚本共享本机状态，不要同时启用远程版与本地版，也不要在多台设备同时控制同一实例。

## 四 首次填写哪些参数

在模块的参数编辑表中填写以下项目。这里是一项一项的文本输入，不需要粘贴整个 JSON。

| 参数 | 第一次如何填写 |
| --- | --- |
| `config_source` | 保持 `module` |
| `account_id` | 保持 `ecs-1` 即可 |
| `account_name` | 自己起一个名称，例如“香港 ECS” |
| `access_key_id` | 将“未设置”替换为你的 RAM AccessKey ID |
| `access_key_secret` | 将“未设置”替换为对应的 AccessKey Secret |
| `region_id` | 与 ECS 所在地域一致，例如香港为 `cn-hongkong` |
| `instance_id` | `i-` 开头的完整实例 ID；仅查流量时保留“未设置” |
| `site_type` | 中国站账号用 `china`，国际站账号用 `international` |
| `max_traffic_gib` | 你希望监控的实际分类额度，单位 GiB；`200` 只是示例 |
| `threshold_percent` | 可先保留 `95` |
| `allow_control` | 保持 `false` |
| `threshold_action` | 保持 `notify` |
| `keep_alive` | 保持 `false` |
| `schedule_enabled` | 保持 `false` |
| `billing` | 先保持 `false`，确认基础查询成功后按需开启 |

点模块右侧的 **⋯**，打开参数编辑项，填写上面的值并保存。没有配置实例、Telegram 或 Webhook 时，对应字段保留“未设置”，不要清空。仅更改密钥不会启用实例控制。

其他参数先保留默认值。关闭日报时，将 `daily_report_time` 填成“关闭”。开关填写小写 `true` 或 `false`；时间填写 `08:00` 这样的 `HH:mm`；额度只填数字，不加 `GB` 字样。参数值不要包含竖线、英文双引号或换行。

`site_type` 表示账号所属中国站／国际站，不是实例地理位置。中国站购买的香港实例仍然填写 `site_type=china`、`region_id=cn-hongkong`。

填写完成后保存，刷新面板即可。**普通参数表模式不运行 `CDT-Setup`，也不要直接打开 JS 文件来代替运行模块中的脚本。** 模块会把你填写的参数传入脚本；直接运行文件没有同样的参数。

## 五 怎样确认安装成功

打开面板并刷新，成功时应看到以下内容；数值仅为展示示例：

```text
CDT Monitor · 只读模式
香港 ECS · 海外账号汇总
12.34 / 200 GiB (6.2%)
实例：运行中
流量时间 2026-10-08 12:00
```

检查名称是否正确、流量时间是否更新、配置了实例 ID 后是否显示对应实例状态。

流量是阿里云账号按国内／海外分类的汇总，不是单台 ECS 的独立流量。默认每 10 分钟执行一次监控；面板刷新本身只查询，不会开关机。以后修改模块参数并保存，下次执行生效。

需要测试通知时，在 Surge 配置脚本列表中运行 `CDT-Notify-Test`；需要手动查询可运行 `CDT-Refresh`。它们都是模块中已经配置好参数的脚本。iOS 支持长按脚本运行或从快捷指令调用。[官方手动运行说明](https://manual.nssurge.com/scripting/generic.html)

## 六 查询成功后再按需打开功能

| 需要的功能 | 模块参数 |
| --- | --- |
| 仅监控和提醒 | 保持 `allow_control=false`、`threshold_action=notify` |
| 达到阈值后停机 | `allow_control=true`、`threshold_action=stop`，并具备 ECS 停机权限 |
| 每天定时启停 | `allow_control=true`、`schedule_enabled=true`，设置 `start_time` 和 `stop_time` |
| 实例停止后尝试保活启动 | `allow_control=true`、`keep_alive=true` |
| 查询余额和实例账单 | 具备相应 BSS 读取权限后设置 `billing=true` |
| Telegram 通知 | `telegram_enabled=true`，填写 `telegram_bot_token` 和 `telegram_chat_id` |

自动控制需要完整实例 ID。定时计划使用 `timezone_offset_minutes`，默认 `480` 即北京时间。设备关机、睡眠、断网或 Surge 停止时可能漏执行，不能保证到达阈值的瞬间停机。

## 七 常见问题

| 现象 | 处理方式 |
| --- | --- |
| URL 无法安装或出现 404 | 使用本说明中的 Raw 地址，不要使用 GitHub 的 `/blob/` 页面地址。检查能否访问 `raw.githubusercontent.com`，仍无法下载时使用第八节本地版。 |
| 脚本下载失败或读取失败 | 远程版在外部资源管理页重试下载；本地版检查两个 JS 是否位于主配置目录。更换文件安装方式时停用旧模块。 |
| 安装后名称或描述为空 | 使用本说明中的新地址更新至 v0.4.1，再重新打开详情；名称为“CDT Monitor 本地版”，描述以“v0.4.1”开头。 |
| 没看到参数编辑表 | 确认安装的是本仓库 v0.4.1 模块且已满足版本要求，重新打开模块详情。 |
| 提示 The value of argument … is not found | 更新为 v0.4.1，保留已有参数，可选项恢复为“未设置”，两项密钥替换为真实值。旧来源按第九节迁移。 |
| 提示 AccessKey 无效或尚未配置 | 检查 `config_source=module`，把凭据填写在模块参数表，保存后刷新；不要运行空白备用 Setup。 |
| 提示 AccessDenied／Forbidden | 核对 RAM 的 CDT、ECS 读取权限；开启了账单时还需 BSS 权限。 |
| 提示 SignatureDoesNotMatch | 检查 AccessKey ID/Secret 是否配对、复制时有无多余空格，并确认设备时间正常。 |
| 提示没有有效实例状态 | 检查 `region_id` 和完整 `instance_id` 是否属于同一个实例，以及凭据能否读取该实例。 |
| 面板显示旧数据或查询失败 | 读取面板中的错误和更新时间；旧数据显示不代表本轮查询成功。修复网络或权限后刷新。 |
| 配置正确但没有面板 | 确认模块和脚本已启用；Mac 检查版本是否至少 5.7.5，iOS 检查相应面板授权。 |
| 点击更新模块仍停在旧版本 | 固定版本或旧根目录来源按第九节迁移到 `/refs/heads/main/surge/`；已经使用新来源则确认版本已发布并等待缓存刷新。 |
| 修改参数后没立刻更新 | 保存／应用模块，再手动刷新面板。若有一轮查询正在运行，待其结束后重试。 |

## 八 本地文件安装备用

从 [标签页](https://github.com/MavisTok/CDT-Monitor-Surge-Loon/tags) 下载对应版本 ZIP 并解压，在 `surge/` 中选择对应平台的 **Local** 模块和两个 JS：

```text
CDT-Monitor-Local.sgmodule      ← iPhone / iPad 使用
CDT-Monitor-Local-Mac.sgmodule  ← Mac 使用，二选一
cdt-monitor.js
cdt-setup.js
```

Mac：在 Surge **更多 → 配置 → 在 Finder 中找到配置** 打开主配置目录，将选中的模块和两个 JS 复制到该目录顶层，再回到模块页启用并填写参数。

iOS：在“文件”App 中找到 Surge 当前使用的主配置目录（iCloud 或本机存储），将选中的模块和两个 JS 放在该目录顶层。同步完成后回到 Surge 模块页启用、填写参数。

相对脚本路径以 **主配置文件所在目录** 为基准。不要只把 ZIP 或整个解压文件夹放进去；不要为本地安装选用不带 `Local` 的远程模块。[官方本地模块说明](https://manual.nssurge.com/profile/module.html)、[脚本路径规则](https://manual.nssurge.com/scripting/overview.html)

## 九 更新模块

### 已使用本说明的持续更新地址

1. 在模块列表找到 **CDT Monitor 本地版**，打开右侧 **⋯ → 更新模块**。
2. 等待下载完成，检查描述中的版本号；检查保存的参数，再应用配置。
3. 若提示脚本下载失败，到外部资源管理页重试。模块会引用与自身版本匹配的 JS，无需另行安装脚本。

保持安装来源 URL 不变。正常更新在同一个模块实例中进行，参数仍由 Surge 保存；本项目沿用原参数名、`account_id` 和持久化 key，历史继续使用。不要每次新建模块。

### 已安装固定版本或旧根目录地址：只需迁移一次

之前给出的固定版本地址只下载指定版本；旧 `/refs/heads/main/CDT-Monitor*.sgmodule` 地址也需要迁移至 `main/surge/`。模块更新不会自动更改设备上保存的来源。

先自行留存参数。如果当前 Surge 提供修改模块来源 URL 的入口，将其改成本说明第二／三节的地址，保存后更新并核对参数。如果没有该入口，停用旧版，从持续更新地址安装一次，填回原参数后启用；仅保留一份启用的 CDT 模块。之后每次都使用该模块的“更新模块”。

不要在持续更新 URL 中加入版本号或每次更换查询参数。如果更新后仍暂时显示旧版本，等待 GitHub Raw 缓存刷新后再更新，无需重装。历史标签和 ZIP 可用于回滚；本地文件版仍需同步替换 Local 模块与 JS，并保留自行填写过的 Setup。

高级多账号、持久化数据编辑器、手动启停参数和全部 29 项参数说明，见 [README](README.md)。

本次可在 Windows 执行 Node 模拟 API 测试；平台适配尚需 Surge/Loon 实机验证，真实阿里云查询与实例控制需要你填写凭据后验证。
